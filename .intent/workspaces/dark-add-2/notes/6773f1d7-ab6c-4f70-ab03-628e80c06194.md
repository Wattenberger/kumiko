# Add theme tokens and store

Introduce dark-theme color tokens and a Svelte store that manages the active theme (`light` | `dark` | `system`), persists it to localStorage, and follows `prefers-color-scheme` when set to `system`.

## Scope
- `public/assets/styles/global.css` — add `[data-theme="dark"]` overrides for the existing CSS variables (`--bg`, `--fg`, `--background-body`, `--background-ui`, `--background-alt`, `--text-main`, `--border`, `--accent-*`, `--gray-*`, `--off-white`, etc.). Keep the existing light-mode values as defaults on `:root`.
- `src/stores/theme.js` (new) — export a `theme` writable store with values `light` | `dark` | `system`, a `resolvedTheme` derived store (`light` | `dark`), and a function to initialize from localStorage. On changes, write `data-theme` on `document.documentElement` and persist to localStorage under key `kumiko-theme`.
- Do NOT modify water.css — override its variables from global.css only.
- Out of scope: redesigning colors, changing the SVG pattern stroke logic, touching worker files.

## Inputs
- Existing tokens in `public/assets/styles/global.css` (lines 1–56)
- Variable usages in `src/components/*.svelte` (e.g. `--accent-darker`, `--accent-lighter`, `--accent-dark`, `--off-white`, `--gray-light`)

## Definition of Done
- New store file exists with `theme`, `resolvedTheme`, and an `initTheme()` helper.
- `global.css` has a `[data-theme="dark"]` block overriding every token that differs between light and dark.
- Setting `document.documentElement.dataset.theme = "dark"` in devtools visibly changes background, text, and accent colors across the app (header, intro, controls, pattern picker, footer).
- No changes to existing light-mode appearance when `data-theme` is unset or `"light"`.

## Verification
- `npm run build` completes without errors.
- `npm run dev` + manual check: toggling `data-theme` attribute in devtools swaps the palette cleanly (no unstyled white/black patches).

# Add theme toggle UI and wire it up

Add a theme toggle control in the header and initialize the theme on app startup using the store from the previous task.

## Scope
- `src/components/pudding/Header.svelte` — add a small toggle button (sun/moon icon or text) on the right side of the header that cycles `light → dark → system` (or a 2-state light/dark toggle — implementer's choice, keep it simple). Bind it to the `theme` store.
- `src/main.js` — call `initTheme()` once on startup so the correct `data-theme` is applied before the app renders (prevents flash of wrong theme).
- `src/components/Canvas.svelte` and `src/components/PatternPicker.svelte` — verify the hardcoded fallback color `stroke: #371863;` (before the `var(--accent-darker)` override) still works in dark mode; if it causes issues in dark mode, remove the hardcoded fallback line (keeping only the `var()`).
- Out of scope: animations beyond a simple CSS transition, a settings panel, keyboard shortcuts.

## Inputs
- The store added in the previous task (`src/stores/theme.js`)
- [Header.svelte](intent://local/note/spec) structure

## Definition of Done
- Clicking the toggle in the header swaps the theme immediately.
- Reloading the page preserves the last-selected theme.
- When the store is set to `system`, the app matches `prefers-color-scheme` and updates live if the OS setting changes.
- No flash of light theme on load when dark is selected.
- Toggle button is keyboard-accessible (focus ring, Enter/Space activates it) and has an `aria-label`.

## Verification
- `npm run build` completes without errors.
- `npm run dev` + manual checks:
  1. Toggle cycles themes and UI updates.
  2. Reload preserves selection.
  3. Change OS dark mode while app is open with theme=system → updates live.
  4. Tab to the toggle, press Enter → theme switches.
